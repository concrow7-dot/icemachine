# Engineering notes

How the code is laid out and the things you need to know before changing it. Kept here, next to the code, so it stays in step. The product side (what we're building and why) is in the decision log and the project brief.

## How the code is laid out

- `src/scenes/`: Title (Quick Play, Story / Continue / New Story; Quick Play dimmed until the uncle's evening is finished; New Story asks With Uncle / On My Own once it has been), StoryIntro, Truck (hub; the PO's drawing with clickable parts), Cooler (prep and restock at home: clipboard with picture add buttons, three 4 x 4 crates, Today's Menu), Drive, Pump, Sales (window, calculator, mini Today's Menu, tip cup, picture orders), Fill (filling an order at the shut cooler: one crate lid open at a time, paper bag, SERVE), DayEnd, Results, Hud, Pause, Loading (`showLoadingWhileLoading(this)` at the end of preload), UncleIntro, TutorialCrawl.
- `src/state/`: EveningState (clock, money, stock, fuel, residents, the customer at the window; `mapId`; the cooler as `coolerSlots` (one per flavour) plus `coolerCells` (48 squares) kept in step by `syncCells()`; restock at home; `pinkSquareFitsOn`), CoolerOrder (the prep draft), Sale (one customer's order; `pictures` and `pictureLine` for picture orders), Residents (buyer kinds: `buyerKind`, `buysTonight`, `sometimesDay`; SCREAM-221: `kindFor` and the instance's `kindOf` (Story: the `days` ticks, 0 = Monday; Quick play: Likelihood), `weekdayOf`, `weekdayName`), CurbFinder, RoadGeometry, AutoRoute (the truck driving itself), Tutorial (the uncle's steps and lines), PriceEntry, HighScores (tables quick, story, tutorial), Records, Damage, StoryRun (run `seed`; `withUncle` makes Day 1 the uncle's evening; `STORY_MAP` is the tutorial map), StorySave (saves the cells and the seed).
- `src/audio/`: Music and songs.
- `src/ui/`: Calculator, TipBar, speechBubble (`drawBubble`), flavourArt (`addFlavourIcon`, `MARKER_FONT` "Permanent Marker", `MENU_COLOURS`), residentLook (`residentsKey()` per map), truckLaps, smoothPixels, truckViews, truckInterior, uncleBox, unclePointer, mapOverview.
- `src/config/`: `tuning.ts` (every tuning number; change values here, not in scenes), flavours, gasStation (`gasStations()` for the current map), `maps.ts` (`MAPS`, `currentMap()`, `setCurrentMap()`), `tutorialRoute.ts`, and generated data (`worcester.ts`, `residents.ts`, `tutorial.ts`, `tutorialResidents.ts`; never edit by hand).
- `src/flow.ts`: scene keys and starting or continuing an evening; the Story run lives in the registry under `story`.
- **Story only by default (decision 076, PO, November 12):** every change applies to Story unless the PO says Quick play gets it too.
- SCREAM-204 (decision 074) and SCREAM-269 (075): `src/state/TruckSpec.ts` (no Phaser, unit-tested): `truckSpec(weak)` gives an evening's truck (`topSpeed`, `accelerationSeconds`, `brakingSeconds`, `creepSpeed`, `coastKeep`, `reverseSpeed`, `reverseAccelerationSeconds`, `maxTurnDegrees`, `turnAboveRoll`, `musicRadius`, `coolerHalfCovered`, `coolerCapacity`, `fuelTankPx`). `evening.spec` is the weak one in Story (any evening with `carry.story`, the uncle's included) and the full one in Quick play; DriveScene, HudScene, CoolerScene, FillScene and `burnFuel` read it instead of the tuning values. The `STORY_*` factors are in `tuning.ts`. Power-ups should change `evening.spec`, not the scenes. The cooler always has 48 squares (`coolerCells`, the save's `cells`); with `coolerHalfCovered` only the left two columns of each crate can be used: `coolerCellOpen(halfCovered, cell)`, `evening.cellOpen(cell)`, and `CoolerOrder` takes the same test as its last argument (`capacity` counts the open squares). The covered halves are drawn by `src/ui/coveredHalf.ts` (`CoolerScene.coveredHalves`, `FillScene.coveredHalves`; in FillScene `lids` are half doors in Story). `StoryRun.finishDay`: out of gas → `FUEL_STORY_OUT_OF_GAS_START` (1/3).
- SCREAM-181: `pauseResults(scene)` in `flow.ts` opens the pause menu over the Results screen while it asks for initials (`PauseScene` gets `fromResults`: no Restart, a text named `high-score-warning`, and Quit stops Results too).
- SCREAM-145: the two maps have names for the player: **Elm Park** (`tutorial`, home) and **Foley Stadium** (`worcester`); code and file names keep the ids. `src/state/RingLaps.ts` (`LapCounter`, `arrivalSpot`, `ringOf`) counts laps of a roundabout (a road with `ring: {x, y, r}`); `EveningState.switchMap()` moves the evening to the other map (`mapId` changes; `homeMapId`, `awayFromHome`, `mapsJoined`, `mapSwitches`); `residents` is a getter for the current map's people (`residentsByMap`). DriveScene `checkLaps` → `goToOtherMap` → `scene.restart()` (preload reloads the other map). Test hooks: `DriveScene.laps` (the counter; `.ring`), `lapsDone`, `lapLabel`; `evening.visits`, `rotaryHintGiven`, `secondVisits`, `countVisit(sale)`; `Sale.toldAboutRotary`.
- SCREAM-229: the portal in the roundabout. `portalStrength(turns, lapsNeeded)` in `RingLaps.ts` (0 on lap 1, up to 1 when the laps are done; `LapCounter.turns` is the laps as a fraction). `src/ui/ringPortal.ts` (`RingPortal`: states lapping, swallowing, closing; `update(strength, dt)` while lapping, `tick(deltaMs)` every frame runs the swallow and the close, at most 1/30 s per frame), `src/ui/portalArt.ts` (the glow and swirl pictures, drawn on canvases once per game), `src/audio/PortalSound.ts` (Web Audio: filtered noise, a wobble and a hum; `setStrength`, `swallow`, `close`, `silence`, `stop`). `goToOtherMap` calls `portal.swallow` then `scene.restart({ viaPortal: true })`; `create` closes the portal when it finds `viaPortal` and clears it (Phaser keeps a scene's start data until a start with new data). Test hooks: `DriveScene.portal` (`shown`, `radius`, `state`, `visible`, `glow`), `DriveScene.portalSound` (`lastEvent`, `level`).
- "Sync rotary hint" (SCREAM-145): copy the Line cell of the "Rotary hint" tab of the Residents sheet (Customers folder; 058) into `ROTARY_HINT_LINE` in `tuning.ts` (one line, no script).
- `tools/`: Python build scripts. `worcester/build_map.py` (the Worcester map from OpenStreetMap data), `tiled/import_tiled.py` and `tiled/build_roads.py` (the tutorial map from the PO's Tiled project in the private art repo; roads from `tools/tutorial/roads.json`), `tiled/export_tiled.py` (Worcester to a Tiled project, SCREAM-211; `import_tiled.py` reads either map, picked by the Tiled file's "map" property), `residents/build_residents.py` (from `residents.csv`; `tutorial` for `tools/tutorial/residents.csv`, which has Windows line endings; `check [tutorial]` lists who would move, with no art and no files written: run it before any build; `build --no-art` rewrites only the .ts when no Look or Age changed; roundabouts are never a resident's street or curb, and each resident's yard spots have their own seed, so one change doesn't shift the rest, SCREAM-230), `truck/build_truck.py`, `uncle/build_uncle.py`, `interior/` and `flavours/` (the PO's cartoon screens and the flavour pictures, drawn at 2x in a wobbly hand-drawn line). The LimeZu singles are the zip in the art repo, unzipped. Worcester rebuilds byte for byte.

## Maps

- `EveningState`'s constructor takes a `mapId` (default `worcester`) and calls `setCurrentMap`; everything else reads `currentMap()`. DriveScene switches map in preload (`useMap`). `startEvening(from, map, guided)`.
- Texture keys: Worcester `map-atlas`, `map-grass`, `map-roads_x_y`, `residents`; tutorial `tut-atlas`, `tut-grass`, `tut-roads_x_y`, `residents-tutorial`. The pump screen always uses Worcester's atlas (it has the pump). Smoothed customer textures are `customer-smooth-<sheet key>-<look>`.
- The map is painted round the camera into one image, repainted per 512 px square. Map sprites are 16 px. With the 1.2x zoom, on-screen labels in DriveScene go through `pin()`. `render.maxTextures` is 1 in `main.ts`.
- Roundabouts (SCREAM-145): Elm Park's is a road with `ring` in `tools/tutorial/roads.json` (`build_roads.py` draws the circle and cuts the grass island); Newton Square in Foley Stadium is drawn by `build_map.py` (`NEWTON_RING_R`, `NEWTON_RING_DX/DY`) after everything is placed, so the rest of the map rebuilds byte for byte (`NO_RING=1` rebuilds it without). The truck arrives on the far side of the ring from the street in (`arrivalSpot`).
- The tutorial map is edited only in Tiled by the PO (everything but roads); `build_map.py`'s tutorial mode would undo his changes. Worcester has a Tiled project too (`tiled/worcester-map/`, SCREAM-211); after its first import is merged, rebuilding Worcester with `build_map.py` would undo his changes. Its residents rebuild with `build_residents.py build <Character_Generator folder>` (no `tutorial`). Street data for new areas comes from the OpenStreetMap API (the cloud workspace can't reach openstreetmap.org; fetch it in a browser: open `api.openstreetmap.org/api/versions`, then `fetch('/api/0.6/map?bbox=...')` in its page and return a trimmed JSON).

## Residents and customers

- 16 x 32 frames; `residents.png` five looks across; front-to-back drawing via `occluders`; depth 5 + y/10000; the truck is 10. At the window the customer is cropped with `setCrop`.
- `Residents.update(dt, ring)`: the ring's centre is the truck's position. States none → running (walking to the truck, plan `follow`) → waiting → window → done. `new Residents(list, rnd, curbs?, story?)`: without a `CurbFinder` they run to their own curb spot (unit-test style); `story` is `{ day, seed }` and picks each one-in-3 buyer's day. `p.buys` says whether they'd buy tonight; `p.decided` once they've heard the truck 30 s without coming. `Residents.chance(heard, likelihood, indoors, regular?)`. Each person's pink square is `p.pickup`.
- Curb spots: `CurbFinder.near(x, y, taken, gap, around?)` tries the nearest street first (150 px, same side), then `further` (400 px along every street within reach, both sides); every stand must pass `standClear` (on the sidewalk) and be within `around` (the truck, 240 px). `Residents.joinSpot` lets a customer share a waiting spot (`spotStand`); DriveScene draws one square per spot and only for customers off the road. The residents build's `curb()` mirrors the game's pink-square check (CAR_CLEAR 80, BAY_CLEAR 100, home, road index).
- Test hooks: `residents.hearingOff`, `residents.callNow(person)` (works on anyone; waits at their own curb and doesn't follow), `residents.wantIceCream(person)`, `Residents.kind`, `Residents.buysTonight`, `DriveScene.pickupZone`, `e.residents.curbs` (`finder.squareFits`, `finder.roads`). Camera lerp: wait about 2.5 s after teleporting the truck in tests.
- The Residents sheet (Drive folder Customers; sheets 15 and 23 until November 9, 058) has a tab per map: "Elm Park" → `tools/tutorial/residents.csv` ("sync tutorial residents"), "Foley Stadium" → `tools/residents/residents.csv` ("sync residents"). The sync copies the columns the build reads (ID, Name, Age, Street, House, Likelihood (%), Look, Notes, Order size, Hinted, Mon to Sun (SCREAM-221: TRUE or FALSE, home that day in Story), From and Until (SCREAM-249)); Picture is the sheet's own. After a sync, run `build_residents.py check` (and `check tutorial`) to see who changes.
- Order sizes: the optional "Order size" column (both tabs) → `Resident.orderSize` → `generateOrder(..., fixedSize)`. The build reads the column only if a sheet has it.
- Schedule lines (SCREAM-247, decision 064): the Residents sheet's "Schedule lines" tab → `tools/schedule/schedule_lines.csv` → `python3 tools/schedule/build_schedule_lines.py` → `src/config/scheduleLines.ts` ("sync schedule lines"). Tags `[Next]`, `[Back]`, `[Home]`, `[Away]` (one kind per line; none = home all 7 days). `src/state/ScheduleLines.ts` (no Phaser, unit-tested): `assignScheduleLines` gives each resident with ticks one line per kind for the run (seed + their id; people home all 7 days get `EVERY_DAY_LINES_EACH` = 3 "every day" lines instead) → `evening.scheduleLinesFor` (both maps; empty outside Story); `kindFits` says whether a kind is true and useful today; `scheduleLineToday` picks one not yet heard tonight (`evening.scheduleLinesHeard`) and fills it. After a paid sale `EveningState.maybeScheduleLine` may call `Sale.addScheduleLine` (`sale.saidSchedule`; never with a hint, not in the uncle's evening; `scheduleLineChance`, `scheduleLinesSaid`, `forceScheduleLine` for tests).
- Neighbour lines (SCREAM-248, decision 065): the "Neighbour lines" tab → `tools/schedule/neighbour_lines.csv` → the same build script → `src/config/neighbourLines.ts` ("sync neighbour lines"). Same tags plus `[Name]` (required) and `[Street]`, all about the neighbour. In `ScheduleLines.ts`: `canBeToldAbout` (ticked days and not 0%), `assignNeighbourLines` (one line per kind per person talked about → `evening.neighbourLinesFor`), `neighbourLineToday(speaker, people, ...)` (someone else on the speaker's street; not in `evening.neighboursToldAbout`, wording not in `scheduleLinesHeard`). `maybeScheduleLine` chooses between the customer's own line and a neighbour's (`neighbourLineShare`, `forceNeighbourLine` for tests) → `Sale.addNeighbourLine` (`sale.neighbourAbout`).
- Hours (SCREAM-249, decision 066): the map tabs' optional "From" and "Until" columns (5:00 PM to 8:00 PM; `clock_minutes` in `build_residents.py`) → `Resident.hours` as `[from, until]` minutes since midnight, either null. `homeAt(resident, minutes)`; `Residents.homeNow(resident)` (Story only; needs `residents.nowMinutes`, which EveningState sets to its clock): out of hours they stay indoors (`step`), don't hear the truck (`rollChances` resets `heard`), and start the evening indoors. Tags `[From]`/`[Until]` in the schedule and neighbour lines (`timeText`). A sync must carry From and Until (both CSVs have the columns).
- Hard-to-find customers (SCREAM-250, decision 067): the map tabs' optional "Hard to find" column (Yes; needs From, Until and a ticked day) → `Resident.hardToFind`. In Story, `Residents.rollChances`: music inside their window (`homeAt`) on a ticked day → they always come; otherwise one roll an evening at their Likelihood (`p.decided`). `homeNow` is always true for them (the hours are a window, not when they're home). `residents.hardToFindOn` is false in the uncle's evening. `EveningState.startSale` sets `sale.tipFactor` (`HARD_TO_FIND_TIP_FACTOR`). Lines: kind `window` (`[From]` and `[Until]` together); `kindFits` gives them only `window`, `home` and `away`; `neighbourLineToday` passes over them half the time (`HARD_TO_FIND_HINT_SKIP`). The clock: 180 game minutes in 300 seconds, so 18 minutes = 30 seconds (the PO's window).
- Hints (SCREAM-103): the Elm Park tab's optional "Hinted" column (Yes) → `Resident.hinted`; the lines are the Residents sheet's "Hint lines" tab → `tools/hints/hint_lines.csv` → `python3 tools/hints/build_hints.py` → `src/config/hintLines.ts` ("sync hint lines"). `assignHints` (`src/state/Hints.ts`, no Phaser, unit-tested) gives each hinted regular one line per run from the run's seed → `evening.hintFor` (empty outside Story). After a tipped paid sale `EveningState.maybeHint` may call `Sale.addHint` (the line becomes "Thanks! ..."; `sale.hintAbout` is the resident's id). Rules in `tuning.ts` (`HINT_*`); `evening.hintChance` (tests set 0 or 1), `evening.paidSales`, `evening.hintsGiven`. Off during the uncle's evening.

## Publishing (the release branch)

- The public site (https://concrow7-dot.github.io/icemachine/) is built from the `release` branch only (`.github/workflows/deploy.yml`; SCREAM-266, decision 068). A merge to `main` publishes nothing.
- **To publish:** open a pull request with base `release` and head `main` (`gh api repos/concrow7-dot/icemachine/pulls -f title="Release: ..." -f head=main -f base=release -F body=@file`), listing the tickets it ships. The PO merges it with **Create a merge commit** (not squash: a squash makes the next release pull request show old changes again and can conflict). The site updates a few minutes later.
- **An urgent fix while main has unreleased work:** branch from `release` (`feature/SCREAM-NN-name`), pull request into `release`; once merged, open a second pull request from `release` into `main` so main gets the fix too.
- **What's live:** compare the two branches (`gh api repos/concrow7-dot/icemachine/compare/release...main --jq '.ahead_by'` is how many commits main is ahead). The build's commit (`VITE_COMMIT`) is the release branch's commit, not main's.
- GitHub's `github-pages` environment only lets listed branches deploy (Settings, Environments, github-pages, Deployment branches and tags): `release` must be on that list or the deploy job is refused.
- "Run workflow" on the Actions page only publishes when started from `release`.

## Tests

- `tests/e2e/`: 16 Playwright suites (`feel drive obstacles extras customers hub sales buy scores pause oneway story residents fuel home tutorial`), about 750 checks. `node tests/e2e/run.mjs [suite ...]`; the runner prints PASS/FAIL lines and only the last 8 lines of a crash; screenshots go to `tests/e2e/.shots`. See `tests/e2e/README.md`.
- Rotation: run the suites that touch the changed code plus a third of the rest; everything for big or risky changes. A PR that changes on-screen text, how many customers come, or the title menu can break checks in any suite: run all suites then.
- Known flaky timing checks: pause patience, extras hit popup, obstacles pothole / road edge / damage popup (pothole "stops on the pothole" also fails on main), feel coasting (fails on main in the cloud workspace), buy's "B returns to truck" (Loading still showing), pause's "Paused at the sales window: the customer's patience stops too" (fails on main, off by one). Rerun alone before worrying.
- The test harness strips TypeScript types without compiling: no constructor parameter properties.

## Working in the cloud workspace

- Clone both repos side by side (`icemachine` and the private `icemachine-art`); `npm install --no-save --no-package-lock` (or the fallback Phaser in `icemachine-art/tooling/phaser-4.2.1`); `npx tsc --noEmit -p .`. Don't commit `package-lock.json`.
- `npm install` brings a newer Playwright than the pre-installed browsers in `/opt/pw-browsers`. Point it at them with a folder of links: `mkdir ~/pwb && ln -s /opt/pw-browsers/chromium-<have> ~/pwb/chromium-<wanted>` (same for `chromium_headless_shell`; the wanted number is in the error), then `PLAYWRIGHT_BROWSERS_PATH=$HOME/pwb node tests/e2e/run.mjs ...`.
- Pushing needs the repo attached with push access; set the fetch refspec and `git push -u`. PRs are opened with `gh api repos/concrow7-dot/icemachine/pulls`.
- Before telling the PO a PR is ready: push everything, then don't push again without saying so. Check a PR's head commit against what was pushed last before marking its ticket Done (PR #117 was merged one commit early).
